# Spec: Export ใบสรุปคำสั่งซื้อเป็น PDF

> สถานะ: **ยืนยันแล้ว** (30 Oct 2026) — พร้อม implement
> แหล่งข้อมูล: ตรวจจากเว็บ demo https://automation-store-eta.vercel.app/ (หน้า Products, Cart, Checkout, Order detail, My Orders)

---

## 1. เป้าหมาย

ผู้ใช้ที่สั่งซื้อสินค้าเสร็จแล้ว สามารถ **ดาวน์โหลดใบสรุปคำสั่งซื้อเป็นไฟล์ PDF ภาษาไทย** ได้ทั้งจากหน้าคำสั่งซื้อและหน้า My Orders
ไฟล์ต้องแสดงว่าสั่งอะไรบ้าง ราคาเท่าไร ส่งไปที่ไหน ส่งแบบไหน และ **คาดว่าจะได้รับของวันไหน**

ปัจจุบันเว็บมีปุ่ม `Download / Print Invoice` แต่เป็นแค่การเรียก `window.print()` (เปิดหน้าต่างพิมพ์ของเบราว์เซอร์) ไม่ได้สร้างไฟล์ PDF จริง ฟีเจอร์นี้จะ **เปลี่ยนปุ่มนี้ให้ดาวน์โหลด PDF แทน**

---

## 2. ระบบปัจจุบัน (As-is)

### 2.1 Flow การสั่งซื้อ

1. หน้า `/products` กด **Add to cart** (ไม่ต้องล็อกอิน ตะกร้าเก็บฝั่ง client)
2. หน้า `/cart` ตาราง Item / Price / Quantity / Total, ยอด `Total: Rs. ...`, checkbox **I agree with the terms of service**, ปุ่ม **Proceed To Checkout** (มีข้อความแจ้งว่าต้องล็อกอินก่อนสั่งซื้อ)
3. ถ้ายังไม่ล็อกอินจะถูกพาไปหน้า `/login`
4. หน้า `/checkout` มี 5 ขั้นตอน (stepper):

| ขั้น | ชื่อ | รายละเอียด |
|---|---|---|
| 1 | Address | Full name, Email, Phone, Address *, Province *, District *, Zipcode *, Country (ดึงค่าเริ่มต้นจากโปรไฟล์ผู้ใช้) |
| 2 | Shipping method | Ground (ฟรี, 3–5 วัน) / 2nd Day Air (Rs. 40, ภายใน 2 วันทำการ) / Next Day Air (Rs. 60, วันทำการถัดไป) |
| 3 | Payment method | Check / Money Order หรือ Credit Card |
| 4 | Payment information | ถ้าเป็นบัตร: เลขบัตร 16 หลัก, ชื่อบนบัตร, Expiry `MM/YY`, CVV 3–4 หลัก |
| 5 | Confirm order | สรุปที่อยู่ การจัดส่ง การชำระเงิน และรายการสินค้า แล้วกด **Place Order** |

5. กด Place Order → `POST /api/orders` → ไปหน้า **`/orders/{id}?placed=1`** (หน้าสุดท้าย)

### 2.2 หน้าสุดท้าย `/orders/{id}?placed=1`

- กล่องสำเร็จ: "Thank you! Your order has been placed." + เลขคำสั่งซื้อ + สถานะ (แสดงเฉพาะเมื่อมี `?placed=1`)
- หัว **Order #{id}** + ปุ่ม `Download / Print Invoice` (`window.print()`)
- "Placed on {วันเวลาสั่ง} · Status: {status}"
- **Shipping Address**: ชื่อ, ที่อยู่, District, Province, Zipcode, Country, Phone, Email
- **Shipping & Payment**: วิธีจัดส่ง, วิธีชำระเงิน (+ เลขบัตร 4 ตัวท้ายถ้าจ่ายด้วยบัตร)
- ตารางสินค้า: Item / Price / Qty / Total
- สรุปยอด: Sub-Total, Shipping, Tax, **Total** (สกุลเงินบนเว็บแสดงเป็น `Rs.`)
- ปุ่ม Continue Shopping

หน้า `/orders/{id}` (ไม่มี `?placed=1`) แสดงเหมือนกันแต่ไม่มีกล่องสำเร็จ
หน้า `/orders` (My Orders) แสดงตาราง Order / Date / Items / Total / Status พร้อมปุ่ม View

### 2.3 ข้อมูลคำสั่งซื้อจาก `GET /api/orders/{id}` (ต้องส่ง `Authorization: Bearer <token>`)

| field | ใช้ใน PDF |
|---|---|
| `id`, `status`, `created_at` | หัวเอกสาร |
| `full_name`, `email`, `phone`, `address`, `city` (District), `state` (Province), `zipcode`, `country` | ที่อยู่จัดส่ง |
| `shipping_method`, `shipping_cost` | การจัดส่ง |
| `payment_method`, `card_last4` | การชำระเงิน |
| `items[]` → `id`, `name`, `price`, `quantity` | ตารางสินค้า |
| `subtotal`, `tax`, `total` | สรุปยอด |

**หมายเหตุ:** ระบบ **ไม่ได้เก็บวันที่จัดส่ง** ต้องคำนวณจาก `created_at` + `shipping_method` (ดูข้อ 4.4)

## 3. ขอบเขตงาน (To-be)

### 3.1 สิ่งที่ต้องทำ

1. **เปลี่ยนปุ่มเดิมในหน้า `/orders/{id}`** (ทั้งแบบมีและไม่มี `?placed=1`)
   - ข้อความปุ่มเปลี่ยนจาก `Download / Print Invoice` เป็น `Download PDF`
   - **คง `data-qa="download-invoice"` ไว้เหมือนเดิม** เพื่อให้ locator เดิมยังหาปุ่มเจอ
   - กดแล้วดาวน์โหลดไฟล์ชื่อ `order-{id}.pdf` ทันที **ไม่เรียก `window.print()` อีกต่อไป**
   - ระหว่างสร้างไฟล์ ปุ่มแสดง `Generating…` และกดซ้ำไม่ได้
2. **เพิ่มปุ่ม PDF ในหน้า My Orders** (`/orders`) ทุกแถว ข้างปุ่ม View
   - ข้อความปุ่ม `PDF`, `data-qa="order-pdf"`
   - ได้ไฟล์เดียวกันกับปุ่มในหน้า order detail
3. **เพิ่ม endpoint** `GET /api/orders/{id}/pdf` ตอบเป็น `application/pdf` พร้อม `Content-Disposition: attachment; filename="order-{id}.pdf"`
   - ใช้สิทธิ์เดียวกับ `GET /api/orders/{id}`
   - ปุ่มทั้งสองจุดเรียก endpoint นี้ QA ทดสอบระดับ API ได้โดยตรง

### 3.2 สิ่งที่ไม่อยู่ในขอบเขต

- เปลี่ยนสกุลเงินหรือภาษาบนหน้าเว็บ (หน้าเว็บยังเป็นภาษาอังกฤษและ `Rs.` เหมือนเดิม เปลี่ยนเฉพาะในไฟล์ PDF)
- การส่ง PDF ทางอีเมล
- ใบกำกับภาษีเต็มรูปแบบ (เลขผู้เสียภาษี ฯลฯ)
- การแก้ไขคำสั่งซื้อ

## 4. เนื้อหาในไฟล์ PDF

### 4.1 โครงสร้างและหัวข้อ (ภาษาไทย ตามลำดับ)

| ส่วน | หัวข้อในไฟล์ | เนื้อหา |
|---|---|---|
| หัวเอกสาร | **ใบสรุปคำสั่งซื้อ** | ชื่อร้าน `AutomationStore`, `เลขที่คำสั่งซื้อ #{id}` |
| ข้อมูลคำสั่งซื้อ | — | `วันที่สั่งซื้อ: …`, `สถานะ: …` |
| ที่อยู่จัดส่ง | **ที่อยู่จัดส่ง** | ชื่อ, ที่อยู่, อำเภอ/เขต (District), จังหวัด (Province), รหัสไปรษณีย์, ประเทศ, `โทร: …`, `อีเมล: …` |
| การจัดส่ง | **การจัดส่ง** | `วิธีจัดส่ง: …`, `ค่าจัดส่ง: …`, `วันที่คาดว่าจะได้รับ: …` |
| การชำระเงิน | **การชำระเงิน** | `วิธีชำระเงิน: …` ถ้าเป็นบัตรแสดง `•••• {card_last4}` เท่านั้น |
| รายการสินค้า | **รายการสินค้า** | ตารางคอลัมน์: `ลำดับ`, `สินค้า`, `ราคาต่อหน่วย`, `จำนวน`, `รวม` |
| สรุปยอด | — | `ยอดรวมสินค้า`, `ค่าจัดส่ง`, `ภาษี`, **`ยอดสุทธิ`** |
| ท้ายเอกสาร | — | `สร้างเอกสารเมื่อ: …` และ `หน้า X / Y` |

ค่าที่มาจากข้อมูลคำสั่งซื้อ (ชื่อสินค้า, ชื่อวิธีจัดส่ง เช่น `Next Day Air`, ชื่อวิธีชำระเงิน, สถานะ) แสดงตามที่ระบบเก็บไว้ ไม่ต้องแปล

### 4.2 สกุลเงิน

- ใช้สัญลักษณ์ **`฿`** นำหน้า และมีตัวคั่นหลักพัน เช่น `฿1,500`
- ถ้าค่ามีทศนิยมให้แสดง 2 ตำแหน่ง เช่น `฿99.50` ถ้าเป็นจำนวนเต็มไม่ต้องมีทศนิยม
- ค่าส่ง 0 แสดงเป็น `฿0`
- **ตัวเลขต้องตรงกับหน้าเว็บทุกค่า** ต่างกันแค่สัญลักษณ์ (`Rs. 1500` บนเว็บ = `฿1,500` ใน PDF)
- เปลี่ยนเฉพาะสัญลักษณ์ ไม่มีการแปลงค่าเงิน

### 4.3 กติกาการแสดงผล

- กระดาษ A4 แนวตั้ง
- รวมของแต่ละแถว = `price × quantity`
- วันที่ใช้รูปแบบไทยทั้งไฟล์ เช่น `30 ต.ค. 2569 14:05` (เดือนย่อภาษาไทย, ปี พ.ศ.) และเขตเวลาเอเชีย/กรุงเทพฯ
- **รองรับภาษาไทย**: ฝังฟอนต์ที่มีอักษรไทย (เช่น Sarabun หรือ Noto Sans Thai) ข้อความไทยต้องไม่เป็นสี่เหลี่ยม สระและวรรณยุกต์ไม่ลอยหรือซ้อนผิดตำแหน่ง
- ข้อความยาว (ชื่อสินค้า ที่อยู่) ตัดขึ้นบรรทัดใหม่ ห้ามล้นขอบกระดาษ
- บรรทัดที่ไม่มีข้อมูล (เช่นไม่มีโทรศัพท์) ให้ซ่อน ห้ามแสดงช่องว่าง `undefined` หรือ `null`
- สินค้าเกิน 1 หน้า: ตารางต่อหน้าถัดไป หัวตารางซ้ำทุกหน้า สรุปยอดอยู่หลังรายการสุดท้าย

### 4.4 วันที่คาดว่าจะได้รับ

นับจากวันที่สั่ง **นับเฉพาะวันจันทร์–ศุกร์ ไม่นับวันหยุดนักขัตฤกษ์**

| shipping_method | วันที่คาดว่าจะได้รับ |
|---|---|
| Next Day Air | วันทำการถัดไป 1 วัน |
| 2nd Day Air | วันทำการที่ 2 |
| Ground | ช่วงวันทำการที่ 3–5 แสดงเป็นช่วง |

ตัวอย่าง (สั่งวันศุกร์ 30 ต.ค. 2569):

| วิธีจัดส่ง | ผลที่ต้องได้ |
|---|---|
| Next Day Air | `2 พ.ย. 2569` (จันทร์) |
| 2nd Day Air | `3 พ.ย. 2569` (อังคาร) |
| Ground | `4–6 พ.ย. 2569` (พุธ–ศุกร์) |

ให้เขียนเป็นฟังก์ชันแยก (pure function) รับ `created_at` และ `shipping_method` เพื่อให้ unit test ได้ง่าย
ถ้าเจอ `shipping_method` ที่ไม่รู้จัก ให้แสดง `-` แทนวันที่ ไม่ให้การสร้างไฟล์ล้มเหลว

## 5. สิทธิ์และกรณีผิดพลาด

| กรณี | ผลที่ต้องได้ |
|---|---|
| ยังไม่ล็อกอิน | ไม่ได้ไฟล์ — หน้าเว็บพาไป login / API ตอบ 401 |
| เปิดคำสั่งซื้อของผู้ใช้อื่น | ไม่ได้ไฟล์ — API ตอบ 403 หรือ 404 |
| ไม่มีคำสั่งซื้อเลขนั้น | API ตอบ 404, หน้าเว็บแสดงข้อความ error |
| สร้างไฟล์ไม่สำเร็จ | แสดงข้อความ `Could not generate PDF. Please try again.` (`data-qa="pdf-error"`) ปุ่มกดใหม่ได้ |

## 6. กรณีทดสอบที่ต้องครอบคลุม (สำหรับ QA)

| # | กรณี | ตรวจอะไร |
|---|---|---|
| 1 | สินค้า 1 รายการ, Ground, Check / Money Order | หัวข้อภาษาไทยครบ, ไม่มีเลขบัตร, วันที่รับเป็นช่วง |
| 2 | หลายรายการ หลายจำนวน, Next Day Air, Credit Card | รวมแต่ละแถวและยอดสุทธิถูก, แสดง `•••• 1234`, ไม่มีเลขบัตรเต็ม |
| 3 | สั่งวันศุกร์ ทั้ง 3 วิธีจัดส่ง | ข้ามเสาร์–อาทิตย์ถูกต้องตามตารางข้อ 4.4 |
| 4 | ชื่อและที่อยู่ภาษาไทย | อ่านออก ไม่เพี้ยน |
| 5 | สินค้ามากจนเกิน 1 หน้า | หัวตารางซ้ำ, เลขหน้าถูก, สรุปยอดอยู่ท้าย |
| 6 | ไม่กรอก Phone / Email | ไม่มีบรรทัดว่าง `undefined` หรือ `null` |
| 7 | ชื่อสินค้ายาวมาก | ตัดบรรทัด ไม่ล้นขอบ |
| 8 | ยอดในไฟล์เทียบกับหน้าเว็บ | ตัวเลขตรงกันทุกค่า, ใช้ `฿` และคั่นหลักพัน |
| 9 | ปุ่มในหน้า order detail (`download-invoice`) | ข้อความ `Download PDF`, ได้ไฟล์ `order-{id}.pdf`, ไม่เปิดหน้าต่างพิมพ์ |
| 10 | ปุ่มในหน้า My Orders (`order-pdf`) | มีทุกแถว, ได้ไฟล์ของคำสั่งซื้อแถวนั้น |
| 11 | ไม่ล็อกอิน / ของคนอื่น / id ไม่มีจริง | ตามตารางข้อ 5 |
| 12 | API `GET /api/orders/{id}/pdf` | content-type `application/pdf`, ชื่อไฟล์ถูก |

แนะนำการตรวจไฟล์ในเทสต์อัตโนมัติ: ดึงข้อความจาก PDF (เช่นด้วย `pdf-parse` หรือ `pdfplumber`) แล้วเทียบกับข้อมูลจาก `GET /api/orders/{id}`

## 7. สิ่งที่ต้องไม่เปลี่ยน (ขอบเขต Regression)

ทุกข้อด้านล่างต้องทำงานเหมือนเดิมหลังเพิ่มฟีเจอร์:

- **Products / Cart**: Add to cart, จำนวนในตะกร้า, ยอดรวม, checkbox terms of service, ปุ่ม Proceed To Checkout และการพาไป login เมื่อยังไม่ล็อกอิน
- **Checkout 5 ขั้นตอน** ลำดับ ชื่อขั้น และปุ่ม Back / Continue / Place Order
- **Validation**: ข้อความ `Please fill in all required address fields`, เลขบัตร 16 หลัก, Expiry `MM/YY`, CVV 3–4 หลัก
- **ค่าส่ง**: Ground 0, 2nd Day Air 40, Next Day Air 60 และยอด Sub-Total / Shipping / Tax / Total ในหน้า checkout
- **หลัง Place Order** ไปที่ `/orders/{id}?placed=1` และแสดงกล่อง "Thank you! Your order has been placed."
- **หน้า order detail** แสดงข้อมูลครบตามข้อ 2.2 ยอดและสกุลเงิน `Rs.` เท่าเดิม
- **หน้า My Orders**: คอลัมน์เดิม และปุ่ม View ยังทำงาน
- **ตะกร้าถูกล้าง** หลังสั่งซื้อสำเร็จ
- **`data-qa` เดิมทั้งหมดห้ามเปลี่ยนชื่อหรือลบ** เพราะเทสต์อัตโนมัติอ้างอิงอยู่ เช่น
  `checkout-heading`, `step-address`, `addr-name`, `addr-email`, `addr-phone`, `addr-address`, `addr-state`, `addr-city`, `addr-zipcode`, `addr-country`, `step-shipping`, `step-payment-method`, `step-payment-info`, `card-number`, `card-name`, `card-expiry`, `card-cvv`, `step-confirm`, `checkout-back`, `checkout-continue`, `place-order`, `order-summary`, `summary-subtotal`, `summary-shipping`, `summary-total`, `checkout-error`, `order-success`, `order-number`, `order-detail`, `download-invoice`, `order-item`, `order-total`, `orders-table`, `order-row`, `order-id`, `order-status`, `view-order`

**การเปลี่ยนแปลงที่ตั้งใจ (ไม่ใช่ regression):** ปุ่ม `download-invoice` เปลี่ยนข้อความเป็น `Download PDF` และดาวน์โหลดไฟล์แทนการเปิดหน้าต่างพิมพ์ เทสต์เดิมที่ตรวจข้อความ `Download / Print Invoice` หรือตรวจว่าเรียก `window.print()` ต้องอัปเดตตาม spec นี้

## 8. แนวทาง implement

- สร้าง PDF ฝั่ง server ผ่าน endpoint ในข้อ 3.1 เพื่อให้ผลเหมือนกันทุกเบราว์เซอร์และทดสอบด้วย API ได้
- library ที่เหมาะ: `pdfkit` หรือ `@react-pdf/renderer` (ฝังฟอนต์ไทยได้) หลีกเลี่ยงวิธีแคปหน้าจอเป็นรูป เพราะข้อความในไฟล์จะค้นหาหรือคัดลอกไม่ได้ และ QA ตรวจข้อความไม่ได้
- แยกฟังก์ชัน pure: คำนวณวันที่รับของ, จัดรูปแบบเงิน `฿`, จัดรูปแบบวันที่ไทย, จัดรูปแบบที่อยู่ — เพื่อ unit test
- ไม่เพิ่ม field ใหม่ในฐานข้อมูล (วันที่รับของคำนวณตอนสร้างไฟล์)

## 10. ข้อสังเกตจากการตรวจเว็บ

- 30 Oct 2026 ช่วงแรก: `GET /api/products` ตอบ **500** (`TypeError: fetch failed`) เพราะโปรเจกต์ Supabase ถูก pause หลัง resume แล้ว API กลับมาทำงานปกติ ตรวจซ้ำแล้วว่าเพิ่มสินค้าลงตะกร้าได้
- **ข้อแนะนำสำหรับเทสต์ end-to-end**: ก่อนรันให้เช็ค `GET /api/products` ว่าตอบ 200 ก่อน ถ้าไม่ใช่ให้หยุดและรายงานว่าระบบล่ม แทนที่จะรายงานว่าเทสต์ fail
- การทดสอบ checkout ต้องมีบัญชีทดสอบ (เก็บใน env หรือ fixture ของโปรเจกต์ ไม่ hard-code ในเทสต์)
